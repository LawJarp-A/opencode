### Problem

Brands are drowning in asset graveyards. They upload 500 photos from a photoshoot, manually tag them for 6+ hours, and then never use 80% of them again. Worse:

- *Zero performance visibility:* No idea which images drive sales
- *Manual hell:* Hours spent tagging, organizing, searching
- *Asset death:* Photos uploaded but never found again
- *Duplicate work:* Reshoot because can't find existing assets
- *Disconnected systems:* DAM doesn't talk to PIM doesn't talk to analytics

*Real user pain:* "I spent 3 hours organizing our Fall photoshoot into folders. Two weeks later I couldn't find the hero jacket image. We ended up using a worse photo because search was terrible."

### Appetite

*6 weeks*

This is foundational infrastructure. Every other feature (Loops, Spaces, Essentials) depends on intelligent asset management. We're investing the time to build it right because this becomes the central nervous system for all brand content.

### Solution

*Files = Living Asset Intelligence Layer*

Not a folder system. Not passive storage. An AI-powered library where every upload triggers:

```
Upload jacket_photo_01.jpg
    ↓
[3 seconds later]
    ↓
✓ Analyzed: "Blue winter jacket, model wearing, outdoor, cloudy"
✓ Linked to: SKU FW25-JACKET-NAVY-M
✓ Scored: Lighting 9/10, Composition 8/10, Brand Fit 8/10
✓ Tagged: jacket, outerwear, lifestyle, winter, model, outdoor
✓ Ready to use

Manual effort: Zero
```

*Key Interactions:*

1. *Drag & drop upload* → Vision AI analyzes in 3 seconds
2. *Auto-links to SKU* → Shows matched product, user can approve/change
3. *Performance overlays* → See CTR/conversion on images used in ads/PDP
4. *Smart grouping* → Detects photoshoot sets, auto-creates collections
5. *Search works* → Type "high performing jacket" → Get results sorted by CTR
6. *Health states* → Track asset lifecycle: Analyzing → Linked → High Performing → Deprioritized

### Rabbit Holes

*Don't build:*

- *Complex folder hierarchies.* No nested folders. Tags + search + filters are enough.
- *Version control system.* Not Git for images. Just "Replace" or "Archive" actions.
- *Advanced image editing.* We have Spaces for that. Files is library, not Photoshop.
- *Manual crop/resize tools.* Use existing Spaces ("Resizer", "Zoom Enhance").
- *Commenting/annotation system.* Phase 2. Focus on intelligence, not collaboration features.
- *Custom metadata fields.* Auto-generated metadata only. No user-defined schemas.

*Reuse existing:*

- Vision AI pipeline (already used in Spaces)
- Performance tracking infrastructure (used in Loops)
- Upload component (if exists elsewhere)
- Masonry grid library (use react-masonry-css or similar)

*Watch out for:*

- *Vision AI failures.* Some images will be unrecognizable. Need graceful fallback.
- *SKU matching edge cases.* New products, variants, similar-looking items.
- *Performance data delays.* Shopify/Meta APIs lag by hours. Set expectations.
- *Storage costs.* 500-image uploads = gigabytes. Compress aggressively.
- *Slow rendering.* 1000+ images in grid = browser chokes. Implement virtualization.

### No-Gos

*Explicitly NOT doing:*

- ❌ Social media publishing (Files stores, doesn't post)
- ❌ Video editing capabilities (future)
- ❌ Collaborative workflows (assign, approve, review) (Phase 2)
- ❌ Public sharing/gallery links (future)
- ❌ Integrations beyond Shopify/Meta (add later incrementally)
- ❌ Mobile app (web-responsive only)
- ❌ Bulk download as ZIP (future nice-to-have)

## 🔧 ENGINEERING PRD

### 1. OBJECTIVE

*Purpose:*
Build an AI-native asset library that automatically analyzes, tags, links, scores, and performance-tracks every uploaded image and video. Transform passive storage into an active intelligence layer that powers all ShopOS content generation and optimization.

*Goal:*

- *Reduce manual tagging time by 80%* (6 hours → 1 hour for 500 images)
- *Increase asset utilization by 2x* (% of uploaded assets actually used)
- *Enable performance-driven decisions* (users can identify top 10% performing assets)
- *Seamless integration* (Files becomes default source for all Spaces workflows)

*Context:*
Files is the *central asset hub* for ShopOS. It sits between:

- *Input:* User uploads, AI generations from Spaces
- *Storage:* Cloud storage (S3/GCS) + metadata DB
- *Output:* Asset selection for Spaces, performance insights for Loops, SKU data for Brand Memory

This is foundational infrastructure. Every feature depends on it.

### 5. CORE REQUIREMENTS

*Upload & Processing:*

1. User can upload 1-500 files via drag/drop or file picker
2. System compresses images to reduce file size by 30-50% without visible quality loss
3. System detects duplicate files (based on hash) and prevents re-upload
4. System shows real-time upload progress (per file + overall percentage)
5. System processes uploads asynchronously (user doesn't wait for analysis to complete)
6. All uploaded files are stored in cloud storage (S3/GCS) with CDN delivery
7. System auto-retries failed uploads (max 3 attempts)

*Vision AI Analysis:*

1. System triggers Vision AI analysis within 3 seconds of upload completion
2. Analysis must complete within 10 seconds for 95% of images
3. Analysis extracts: objects, scene type, colors, text (OCR), product type
4. Quality scoring rates: lighting, composition, focus, exposure, brand fit (0-10 scale)
5. Brand fit score compares image to brand style guidelines from Brand Memory
6. Analysis results are stored and displayed in asset metadata
7. If analysis fails, asset enters "Needs Review" state and user is notified

*SKU Auto-Linking:*

1. System compares uploaded image to product catalog using visual similarity
2. Confidence scoring:
    - ≥85%: Auto-link, no approval needed
    - 65-84%: Suggest link, requires user approval
    - <65%: No suggestion, manual link only
3. Multi-product detection: identify up to 5 SKUs in one image
4. User can approve/reject suggestions via modal
5. User can manually link/unlink SKUs via product picker
6. Bulk actions: approve all high-confidence suggestions at once
7. Linked SKUs display as chips on asset card

*Grid Display & Organization:*

1. Masonry grid layout (Pinterest-style, responsive columns)
2. Virtual scrolling (only render visible items, handle 10,000+ assets)
3. Lazy-load images (load 50px before entering viewport)
4. Mixed display: uploads + AI generations in same grid
5. Auto-grouping: system detects photoshoot sets (based on date, metadata, visual similarity) and creates Smart Collections
6. Smart Collections appear above main grid
7. Assets display source badge (Upload vs AI Gen) and health state badge

*Search & Filter:*

1. Search is real-time (updates as user types, debounced 200ms)
2. Search matches: filename, tags (auto + manual), linked SKUs, description
3. Visual similarity search: user uploads/selects image, system finds visually similar assets
4. Filters: output type (image/video), health state, date range, performance tier, linked/unlinked status
5. Filters are multi-select and combinable
6. Sort options: date uploaded (desc), performance (desc), quality score (desc), last used (desc)
7. Search/filter state persists during session

*Performance Tracking:*

1. System syncs Shopify analytics daily (product views, ATC rate, sales)
2. System syncs Meta Ads data every 4 hours (impressions, CTR, ROAS)
3. System syncs email platform data daily (clicks, click rate)
4. Assets used in multiple placements show aggregated metrics
5. Performance badges auto-update: Top 10% (green), Above Avg (yellow), Below Avg (grey)
6. "Where Used" section shows all active placements with status (live/paused/ended)
7. Historical charts display 7/30/90 day performance trends

*Asset Detail View:*

1. Click asset card opens slide-over detail panel (doesn't navigate away)
2. Panel displays: full preview, metadata, quality scores, linked SKUs, performance, tags, actions
3. User can replace asset (uploads new file, preserves metadata + links)
4. User can archive asset (removes from main grid, preserves data, recoverable)
5. User can download original file
6. User can copy CDN URL to clipboard
7. Panel is keyboard-navigable (arrow keys to next/previous asset)

*Health States:*

1. Assets transition through health states:
    - *Analyzing:* Initial upload, Vision AI processing
    - *Linked:* SKU-linked, ready to use
    - *High Performing:* Top 10% performance across any platform
    - *Deprioritized:* Bottom 25% performance or unused for 90+ days
    - *Archived:* User-archived or system-archived (unused 180+ days)
2. Health state badges display on asset cards
3. Filters allow viewing by health state
4. System auto-updates health states daily based on performance data

*Integration:*

1. Assets are selectable in all Space workflows (product selector shows Files assets)
2. AI generations from Spaces auto-appear in Files within 5 seconds
3. Shopify product sync runs every 6 hours (or webhook-triggered)
4. Meta Ads assets can be pushed to Meta library (one-click export)
5. Brand Memory style guidelines feed into brand fit scoring

### 6. BEHAVIORS & RULES

*Upload Behavior:*

- *Compression:* Automatically compress JPG/PNG to WebP (30-40% size reduction), preserve original in cold storage
- *Duplicate Detection:* Hash file on client, check against DB before upload, show "This file already exists" modal with option to view existing or upload anyway (as new version)
- *Batch Processing:* Process uploads in parallel (max 10 concurrent), queue remaining
- *Progress Updates:* WebSocket connection for real-time progress (fallback to polling every 2s)
- *Failed Uploads:* Show red "X" icon, "Retry" button, error message ("Network error" or "File too large")
- *Unsupported Formats:* Show toast notification: "Format not supported. Please upload JPG, PNG, WEBP, HEIC, MP4, or MOV."

*Vision AI Analysis Behavior:*

- *Trigger:* Immediately after upload completes
- *Queue:* Process in FIFO order (first uploaded, first analyzed)
- *Timeout:* If analysis exceeds 30 seconds, mark as "Needs Review" and continue
- *Retry:* Auto-retry failed analyses once after 60 seconds
- *Graceful Degradation:* If Vision AI is down, assets enter "Linked" state without scores (user can manually tag)
- *Progress Indicator:* "Analyzing..." badge with spinner on asset card

*SKU Linking Behavior:*

- *Auto-Link (≥85% confidence):*
    - Automatically link, show checkmark badge
    - No modal interruption
    - Log to analytics
- *Suggest (65-84% confidence):*
    - Show modal after analysis completes
    - Display side-by-side comparison (uploaded image vs catalog image)
    - "Approve" button (green), "Reject" button (grey), "Choose Different" (opens picker)
    - User can batch-approve all suggestions
- *Manual (<65% confidence):*
    - No auto-link
    - User can click "Link to SKU" button in detail panel
    - Opens product picker (search catalog, select product)
- *Multi-Product:*
    - If ≥2 products detected, show all suggestions in modal
    - User can approve each individually or all at once
- *Unlink:*
    - User can click "X" on SKU chip to unlink
    - Confirmation modal: "Unlink [Product Name]?"
    - Unlinking doesn't affect other assets linked to same SKU

*Performance Tracking Behavior:*

- *Shopify Attribution:*
    - Match product page images to Files assets via URL or SKU
    - Calculate ATC rate: (add_to_cart_events / product_page_views) × 100
    - Update daily at 2am UTC
- *Meta Ads Attribution:*
    - Match ad creative images to Files via URL hash or direct upload tracking
    - Pull metrics from Meta Ads API (impressions, clicks, CTR, ROAS)
    - Update every 4 hours
- *Email Attribution:*
    - Match image URLs in email campaigns to Files assets
    - Track clicks from email platform API
    - Update daily at 3am UTC
- *Performance Badges:*
    - *Top 10%:* Asset is in top 10% of all assets by aggregated performance score
    - *Above Average:* Asset is above median performance
    - *Below Average:* Asset is below median performance
    - Recalculate daily
- *"Where Used" Tracking:*
    - Log every time asset is used (Shopify PDP, Meta Ad, Email, Space generation)
    - Track status: Active, Paused, Ended, Removed
    - Update status based on platform data (e.g., ad campaign ends → status = "Ended")

*Health State Transition Rules:*

1. *Upload → Analyzing:* Immediately on upload
2. *Analyzing → Linked:* After Vision AI completes (regardless of SKU link)
3. *Linked → High Performing:* When asset enters Top 10% performance tier
4. *Linked → Deprioritized:* When asset is unused for 90 days OR in bottom 25% performance for 30 consecutive days
5. *Any State → Archived:* When user manually archives OR system auto-archives (unused 180 days)
6. *Analyzing → Needs Review:* If Vision AI times out or fails

*Smart Collection Auto-Grouping:*

- *Trigger:* Run grouping algorithm after each upload batch completes
- *Criteria for Grouping:*
    - Same upload session (batch uploaded within 10 minutes)
    - Visual similarity (embeddings within 0.85 cosine similarity)
    - Same date in EXIF metadata
    - Sequential filenames (e.g., IMG_001.jpg, IMG_002.jpg)
- *Naming:* "Campaign Set: [Date]" or use detected keywords (e.g., "Winter Outdoor")
- *Minimum Size:* 5 assets to create collection
- *User Actions:* User can rename, merge, split, or delete collections

### 7. TECHNICAL CONSTRAINTS & EDGE CASES

*Performance Requirements:*

- *Page Load:* <1 second to first meaningful paint (grid with first 20 assets)
- *Search Response:* <200ms to update grid after search query
- *Filter Update:* <100ms to update grid after filter change
- *Upload Speed:* Target 5MB/sec per file (may vary by user network)
- *Vision AI Processing:* <10 seconds for 95% of images, <30 seconds maximum
- *Asset Card Render:* 60 FPS scrolling even with 1000+ assets visible
- *Virtual Scroll:* Load 50 assets ahead, unload assets 200px out of view

*Scalability Constraints:*

- *Max Assets per Brand:* 100,000 (soft limit, paginate/archive beyond)
- *Max Upload Batch:* 500 files (hard limit, enforced client-side)
- *Max File Size:* 50MB per file (reject larger files with clear error)
- *Storage per Tier:*
    - Free: 1GB
    - Pro: 50GB
    - Enterprise: 1TB (custom pricing beyond)
- *API Rate Limits:*
    - Shopify: 2 calls/second (respect rate limit headers)
    - Meta Ads: 200 calls/hour per user (queued)
    - Vision AI: 100 concurrent requests (queue beyond)

*Error Handling:*

*1. Upload Errors:*

- *Network failure:* Retry 3 times, then show "Upload failed. Check connection and retry."
- *File too large:* Show immediately: "File exceeds 50MB limit. Compress or select smaller file."
- *Unsupported format:* Show: "Format not supported. Use JPG, PNG, WEBP, HEIC, MP4, MOV."
- *Storage limit exceeded:* Show: "Storage limit reached. Upgrade plan or delete assets."
- *Server error (5xx):* Retry 3 times, then show: "Server error. Try again in a few minutes."

*2. Vision AI Errors:*

- *Timeout (>30s):* Mark asset as "Needs Review", log error, continue processing queue
- *API down:* Queue for retry (1 hour), show "Analysis delayed" badge
- *Unrecognizable image:* Return empty analysis, asset still usable, suggest manual tags

*3. SKU Linking Errors:*

- *No products in catalog:* Show: "No products found. Sync your Shopify catalog first."
- *API failure:* Disable auto-linking temporarily, allow manual linking
- *Ambiguous match:* If multiple products have similar confidence (within 5%), show all in suggestion modal

*4. Performance Data Errors:*

- *Shopify API rate limit:* Queue requests, process in next sync cycle
- *Meta API auth expired:* Show admin warning: "Reconnect Meta Ads account"
- *Missing attribution:* If asset used but can't attribute (URL changed), show "Performance data unavailable"

*Edge Cases:*

*1. Duplicate Files:*

- *Same file uploaded twice:* Show modal: "This file already exists. View existing or upload as new version?"
- *Similar files (different compression):* Allow both, mark as "Similar" in UI (future: auto-detect near-duplicates)

*2. Orphaned Assets:*

- *Linked SKU deleted from Shopify:* Show warning badge: "Linked product no longer exists. Relink or archive."
- *Ad campaign ended:* Update "Where Used" status to "Ended", keep performance data

*3. Large Batches:*

- *500 file upload:* Process in queue, show progress: "Uploading 235/500, Analyzing 127/500"
- *10,000+ assets in grid:* Virtual scroll essential, paginate API calls (50 per request)

*4. Slow Network:*

- *Upload stalls:* Show spinner, allow cancel, resume on reconnect (if supported by cloud storage)
- *Images won't load:* Show grey placeholder with filename, retry button

*5. Missing Metadata:*

- *No EXIF data:* Use upload timestamp as fallback date
- *No SKU match:* Asset still usable, just unlinked

*6. AI Hallucinations:*

- *Wrong object detection:* User can edit tags, report issue (feedback loop to improve model)
- *Incorrect brand fit score:* User can override (future: train custom brand fit model)

*Browser Compatibility:*

- Chrome/Edge/Safari (last 2 versions)
- Firefox (last 2 versions)
- iOS Safari 14+
- No IE11 support

*Accessibility:*

- *Keyboard Navigation:* Tab through assets, arrow keys to navigate grid, Enter to open detail panel
- *Screen Readers:* Alt text for all images, ARIA labels for all interactive elements
- *Color Contrast:* WCAG 2.1 AA compliance for all text and badges
- *Focus Indicators:* Clear visual focus states for keyboard users
