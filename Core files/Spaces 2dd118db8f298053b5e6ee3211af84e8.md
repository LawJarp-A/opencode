## 📋 Let’s Shape It

### Problem

Users are blind to 90% of ShopOS capabilities. With 57+ Spaces, they:

- Only use the 3-4 they stumbled upon during onboarding
- Don't know which Space solves their current problem
- Can't distinguish beta/experimental Spaces from production-ready ones
- Enterprise users can't find their custom-curated Spaces

**Result:** Low feature adoption, frustrated users, support tickets asking "can ShopOS do X?" when Space #34 already does it.

### Appetite

### **2 weeks**

We're willing to invest the time to get discovery right because every other feature depends on users actually finding it.

### Solution

**One dedicated "Spaces" page.** Think app store, not settings menu.

### Rabbit Holes

**Don't build:**

- **Sorting algorithms.** Alphabetical is fine for v1. Popularity/recommendations come later.
- **Favorites/bookmarks.** Users will just search. Add when data shows it's needed.
- **Custom admin panel.** Devs hard-code Space metadata in config file for now.
- **Public API/WordPress integration.** Internal tool first. Expose later if needed.

**Reuse existing:**

- Space form logic (already built)
- Search component (exists in Files?)
- Filter UI patterns (copy from existing product)

**Watch out for:**

- **Enterprise visibility logic.** Don't leak custom Spaces to wrong users. Test this heavily.
- **Image loading performance.** 57 preview images = slow page. Lazy load everything below fold.
    
    ### No-Gos
    
    **Explicitly NOT doing:**
    
    - ❌ Sort by popularity/recent/alphabetical (future)
    - ❌ Favorite/pin Spaces (future)
    - ❌ Space usage analytics in the UI ("You used this 3 times") (future)
    - ❌ Mobile app version (web-only for now)
    - ❌ Onboarding tour/walkthroughs (ship discovery first, education second)

## 🔧 ENGINEERING PRD

### FEATURE: Spaces Directory

---

### 1. OBJECTIVE

**Purpose:**

Build a dedicated "Spaces" page that acts as the primary discovery surface for all ShopOS capabilities. Users can browse, search, filter, and launch Spaces from one unified catalog.

**Goal:**

- Increase Space usage from ~3 Spaces/user to 8+ within 30 days
- Reduce "How do I do X?" support tickets by 40%
- Enable Enterprise custom Space distribution without fragmenting UX

**Context:**

This is a **new top-level page** in the app, accessible via:

- Side navigation (persistent)
- Homepage nudge/CTA at end of feed

All 57 spaces as a part of the directory so far can be found here:

[Spaces-57.md](Spaces/Spaces-57.md)

---

### 2. SCOPE

**In Scope:**

- Dedicated `/spaces` route
- Grid display of all Spaces (57 currently, scales to 100+)
- Real-time search across Space name/description/tags
- Multi-select filters (Image/Video/Text output types)
- Status badges (Beta, Custom, Standard)
- Enterprise-specific Space visibility controls
- "Know More" modal per Space (About, Best For, Not Good For, Templates)
- Performance: Page load <200ms, search/filter updates <100ms
- Analytics instrumentation (page views, searches, filters, clicks)

**Out of Scope (Future Iterations):**

- Sort functionality (alphabetical, recent, popular)
- Favorites/bookmarking
- Admin panel for Space metadata management
- Public API for WordPress/external sites
- Mobile-specific optimizations
- Onboarding tooltips/guided tours

**Phase:** Phase 1 (Foundation) - Ships in 6 weeks

---

### 3. INPUTS

**Data Sources:**

1. **Space Metadata Configuration** (JSON/DB):
    - `space_id` (string, unique)
    - `name` (string, 50 char max)
    - `subheading` (string, 100 char max)
    - `description` (string, 300 char max)
    - `output_type` (enum: "image", "video", "text")
    - `status` (enum: "standard", "beta", "custom")
    - `preview_image_url` (string, absolute URL)
    - `tags` (array of strings for search)
    - `visibility` (object: `{ all: true }` OR `{ enterprise_ids: ["agilitas", "hamleys"] }`)
    - `about` (string, markdown)
    - `best_for` (array of strings)
    - `not_good_for` (array of strings)
    - `templates` (array of objects: `{ name, preview_url }`)
2. **User Session Data:**
    - `user_id` (for analytics)
    - `enterprise_id` (null if not enterprise, string if enterprise user)
    - `tier` (free/pro/enterprise)

**User Actions:**

- Navigate to `/spaces` via side nav or homepage nudge
- Type search query
- Click filter chips (multi-select)
- Click Space card to launch
- Click "i" icon to open "Know More" modal
- Click "Launch" button on card or in modal

### 5. CORE REQUIREMENTS

**Must Have:**

1. **Page Access:** User can navigate to Spaces page from side nav and homepage nudge in ≤1 click
2. **Grid Display:** All Spaces visible to user are shown in responsive grid (3-4 columns desktop, 2 mobile, 1 compact mobile)
3. **Search:** User can type query and see results update in real-time (<100ms) by matching Space name, description, or tags (fuzzy search, case-insensitive)
4. **Filters:** User can select multiple output types (Image/Video/Text) and grid updates to show only matching Spaces
5. **Status Badges:** Beta Spaces show "BETA" badge; Custom Spaces show "CUSTOM: [Brand Name]" badge; Standard Spaces have no badge
6. **Enterprise Visibility:** Custom Spaces only visible to users in `visibility.enterprise_ids` array; all users see Standard Spaces; Beta visibility follows same rules as Standard unless explicitly restricted
7. **Launch Action:** Clicking "Launch" button or Space card opens the Space's input form in the main content area (existing behavior, just triggered from new entry point)
8. **Know More Modal:** Clicking "i" icon opens modal with 4 tabs (About, Best For, Not Good For, Templates); modal is dismissible; "Launch Space" button in modal footer triggers same action as card's Launch button
9. **Performance:** Initial page load <200ms; search/filter interactions update UI <100ms; images lazy-load below fold
10. **Analytics:** Track `spaces_page_viewed`, `space_searched`, `space_filtered`, `space_selected` events with relevant metadata

### 6. BEHAVIORS & RULES

**Search Behavior:**

- Matches against `name`, `description`, and `tags` fields
- Partial matches allowed (e.g., "back" matches "Background Remover", "New Backdrop")
- Search is **additive** with filters (e.g., search "studio" + filter "Image" = only image-output Spaces with "studio" in name/desc)
- Clear search resets to full filtered list (or full list if no filters active)

**Filter Behavior:**

- Filters are **multi-select** (user can select Image + Video to see both)
- If zero filters selected = show all Spaces (equivalent to all 3 selected)
- Filter chips show count badge (e.g., "Images (23)")
- Clicking active filter deselects it
- Filters persist during session (localStorage or session state)
- "Reset" button clears all filters and search

**Badge Display Rules:**

- If `status === "beta"` → show "BETA" badge (orange/yellow)
- If `status === "custom"` → show "CUSTOM: [Brand]" badge (purple/brand color)
- Standard Spaces (`status === "standard"`) → no badge
- Badges always visible (not hidden on hover)

**Enterprise Visibility Logic:**

- On page load, check `user.enterprise_id`
- Filter Spaces where:
    - `visibility.all === true` (Standard/Beta global Spaces) OR
    - `user.enterprise_id` is in `visibility.enterprise_ids` array (Custom Spaces)
- Do NOT show Custom Spaces from other enterprises
- If user is not enterprise (`user.enterprise_id === null`), only show Spaces with `visibility.all === true`

**Card Click Behavior:**

- Clicking **anywhere on card** except "i" icon → Launch Space (open form)
- Clicking **"i" icon** → Open Know More modal (do not launch Space)
- Clicking **"Launch" button** in modal → Close modal + Launch Space

**Modal Behavior:**

- Modal overlays current page (does not navigate away)
- Clicking outside modal OR "X" button → Close modal
- "Launch Space" button in footer → Close modal + Trigger Space launch
- Tab navigation keyboard-accessible

**Image Loading:**

- Preview images lazy-load using Intersection Observer (images below fold don't load until scrolled into view)
- Placeholder: Grey shimmer box with Space name overlay (no broken image icons)
- If image fails to load: Show fallback icon based on output type (📸/🎬/✍️)

**Empty States:**

- **No search results:** "No Spaces match '[query]'" + "Clear search" button
- **No filter results:** "No Spaces match selected filters" + "Reset filters" button
- **No Spaces available (edge case):** "No Spaces available yet. Check back soon!"

### 7. TECHNICAL CONSTRAINTS & EDGE CASES

**Performance Requirements:**

- Initial page load: <200ms (time to first meaningful paint)
- Search/filter updates: <100ms (debounce search input by 150ms)
- Image lazy loading: Load images 200px before entering viewport
- Maximum grid size without pagination: 200 Spaces (current count: 57, so safe)

**Data Constraints:**

- Space names: Max 50 characters (truncate with "..." if exceeded in UI)
- Subheadings: Max 100 characters (truncate at 2 lines in card)
- Preview images: Max 5MB per image (compress on upload), serve as WebP with PNG fallback
- Tags: Max 20 per Space (for search indexing)

**Error Handling:**

- If Space metadata fails to load → Show error banner: "Failed to load Spaces. [Retry]"
- If preview image fails → Show fallback icon
- If search crashes (unlikely) → Catch error, show all Spaces, log to Sentry
- If user clicks Launch but Space is unavailable (deprecated/removed) → Show toast: "This Space is no longer available"

**Edge Cases:**

1. **User has no eligible Spaces (enterprise user, no custom Spaces assigned):**
    
    → Show standard Spaces only, no empty state
    
2. **Space has no preview image (`preview_image_url` is null):**
    
    → Use fallback icon based on `output_type`
    
3. **Space has no tags:**
    
    → Only searchable by name/description
    
4. **User types very long search query (>200 chars):**
    
    → Truncate query to 200 chars, show warning toast
    
5. **Browser doesn't support lazy loading (old browsers):**
    
    → Load all images immediately (graceful degradation)
    
6. **User has slow network:**
    
    → Show shimmer loading state for cards (skeleton screens)
    
7. **Space name has special characters/emojis:**
    
    → Render as-is (UTF-8 support required)
    

**Browser Compatibility:**

- Chrome/Edge/Safari (last 2 versions)
- Firefox (last 2 versions)
- iOS Safari 14+
- No IE11 support required

**Rate Limits:**

- None (client-side filtering, no API calls for search/filter)

### 8. EXAMPLES

**Example 1: User searches for "background"**

- **Input:** User types "background" in search bar
- **Expected Output:** Grid shows "Background Remover" (Space #34) and "New Backdrop" (Space #35)
- **Behavior:** Other Spaces fade out/hide; result count updates to "Showing 2 Spaces"

**Example 2: User filters for "Video" output type**

- **Input:** User clicks "Videos" filter chip
- **Expected Output:** Grid shows only Spaces where `output_type === "video"` (e.g., Product Clip, 360 Spin, Vibe Video, Ad Spot, Social Reel)
- **Behavior:** Filter chip highlights as active; count badge shows total video Spaces; Image/Text Spaces hidden

**Example 3: Enterprise user (Agilitas) sees custom Space**

- **Input:** User with `enterprise_id: "agilitas"` loads Spaces page
- **Expected Output:** Grid includes Space #58 "Brand Pack" (custom Space, visible only to Agilitas users) with badge "CUSTOM: Agilitas"
- **Behavior:** Other enterprise users (e.g., Hamleys) do NOT see "Brand Pack"; only Agilitas users see it

**Example 4: User clicks "Know More" on Fashion Studio**

- **Input:** User clicks "i" icon on "Fashion Studio" card (Space #1)
- **Expected Output:** Modal opens with 4 tabs; "About" tab shows: "Get a pro studio look for your clothing items. [Full description from config]"; "Best For" tab shows bulleted list; "Templates" tab shows 3 example output images
- **Behavior:** Modal overlays page; clicking "Launch Space" button closes modal and opens Fashion Studio form

**Example 5: User searches "studio" and filters "Image"**

- **Input:** User types "studio", then clicks "Images" filter
- **Expected Output:** Grid shows only image-output Spaces with "studio" in name/description (e.g., Fashion Studio, Product Studio)
- **Behavior:** Combined logic: (search match) AND (filter match); Video Spaces like "Product Clip" (which might mention "studio") are hidden because filter excludes them

### 11. ASSUMPTIONS

**We assume:**

1. Space metadata is static (updated via code deploy, not user-generated content)
2. Space count will grow to ~100 in next 6 months, but not to thousands (so client-side filtering is viable)
3. Enterprise users already have `enterprise_id` in session/auth context
4. Preview images are hosted on CDN (fast delivery globally)
5. Existing Space form logic can be triggered via URL parameter or function call (e.g., `openSpace(spaceId)`)
6. Users understand basic e-commerce/design terminology (we don't need to explain "lifestyle shot" vs "studio shot")

**We do NOT assume:**

1. Users know keyboard shortcuts (must be mouse-navigable)
2. Users have high-speed internet (must work on 3G)
3. Users have large screens (must work on mobile)
