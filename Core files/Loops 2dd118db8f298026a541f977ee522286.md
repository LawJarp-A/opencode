# 📋 SHAPE UP PITCH

## Problem

Brands using AI are stuck in the casino. They generate 20 ad creatives, post them, see mixed results, then generate 20 more next week. Zero learning between cycles. Performance stays flat or declines.

*The pattern:*

```
Week 1: Generate 20 images → Post to Meta → Some work, most don't
Week 2: Generate 20 more → Post again → Still guessing
Week 12: No better than Week 1
Week 52: Competitors using same AI, same results
```

*Real user pain:* "We spent $50K on AI-generated ads last quarter. We have no idea which creative patterns actually work. We're just throwing spaghetti at the wall every week and hoping something sticks."

*The cost:*

- Wasted ad spend on underperforming creatives (60-70% of generated content never converts)
- No compounding advantage (competitors can copy your AI prompts)
- Manual analysis required to identify patterns (teams spend 10+ hours/week analyzing performance)
- Can't scale testing without scaling team (human bottleneck)

*Why this matters:* AI content generation is table stakes. Every competitor can use Midjourney. The differentiation is learning. Brands that compound intelligence week-over-week will dominate. Those that don't will stay stuck.

## Appetite

*6 weeks*

This is THE differentiator. Loops transform ShopOS from "AI content tool" (commodity) to "self-improving commerce system" (moat). We're willing to invest heavy because this is what makes brands 2x better in 6 months, not 2% better today.

## Solution

*Loops = The Scientific Method for Commerce*

Not just generate. Generate → Test → Measure → Learn → Improve → Repeat ∞

*The Loop:*

```
Week 1: Generate 20 product images
  ↓
Mode 1: SIMULATE
  AI agents (calibrated to your store's data) predict which will perform best
  Result: "Images with warm tones + close-ups will outperform by 35%"
  ↓
Mode 2: LISTEN
  Show top 5 predicted winners to real users in swipeable story interface
  Users vote, explain preferences in exchange for rewards
  Result: "Users prefer #3 because 'the product looks touchable'"
  ↓
Mode 3: TEST
  Deploy winning variants to live traffic (A/B test on Shopify PDP)
  Measure real CTR, add-to-cart rate, conversions
  Result: Image #3 drives 2.4% CTR (vs 1.2% baseline) = 100% improvement
  ↓
RL Model analyzes: "Warm tones + close-ups + texture visibility = winner"
  ↓
Week 2: Generate 20 new images
  70% incorporate learned pattern (warm tones, close-ups, texture)
  30% explore new directions (avoid local maxima)
  ↓
Deploy, measure, learn, repeat
  ↓
Week 8: Performance +40% vs Week 1
Week 52: Performance +100% vs Week 1

Your competitors' AI stays dumb. Yours gets smarter every week.
```

*Key Interactions:*

1. *Start Loop:* One-click from any Space → Simple modal (5 questions)
2. *Simulate:* AI agents predict winners → Heatmaps, CTR forecasts, friction analysis
3. *Listen:* Story-style UI → Users swipe, vote, explain → Qualitative insights
4. *Test:* Deploy to live traffic → A/B split → Measure real performance
5. *Learn:* RL model extracts patterns → Biases next generation
6. *Dashboard:* See all Loops, performance trends, learned patterns, next generation countdown

## Rabbit Holes

*Don't build:*

- *Complex RL infrastructure from scratch.* Use existing pattern recognition libraries (TensorFlow, PyTorch). Focus on feature extraction, not building neural nets.
- *Real-time A/B testing analytics.* Batch updates every 4-6 hours are fine. Users don't need second-by-second dashboards.
- *Multi-variate testing (testing 10+ variables at once).* Start simple: 2-5 variants per generation. Add complexity later.
- *Custom reward systems for Listen mode.* Use existing discount code system. Don't build points/gamification infrastructure.
- *Cross-Loop pattern sharing.* Phase 2. Keep Loops isolated for now.
- *Manual pattern override UI.* Trust the RL model. If users want control, they pause the Loop and regenerate manually.

*Reuse existing:*

- Space execution engine
- Performance tracking connectors
- Brand Memory
- Agent system

*Watch out for:*

- Statistical significance (need robust thresholds)
- Seasonality (normalize for external factors)
- API rate limits (batch intelligently)
- Broken attribution (need fallbacks)
- User expectation mismatch (set clear timelines)

## No-Gos

*Explicitly NOT doing:*

- ❌ Real-time optimization (updates every 4-6 hours)
- ❌ Cross-Loop learning (Phase 2)
- ❌ Multi-objective optimization (Phase 2)
- ❌ Manual pattern editing (Phase 2)
- ❌ Social media publishing automation
- ❌ Budget management
- ❌ Audience targeting
- ❌ Integrations beyond Shopify/Meta/Amazon

# 🔧 ENGINEERING PRD

## 1. OBJECTIVE

*Purpose:*
Build a continuous improvement system that transforms AI-generated content from static outputs into self-optimizing workflows. Loops enable brands to generate, test (via Simulate/Listen/Test), measure, learn, and improve infinitely—compounding intelligence week-over-week.

*Goal:*

- *15%+ performance improvement by Generation 3* (vs baseline)
- *100 active Loops within 30 days* post-launch
- *2x retention for Loop users* vs non-Loop users at 90 days
- *Time to first learning: <14 days* for 80% of Loops

*Context:*
Loops are ShopOS's core differentiation. While competitors offer AI content generation (commodity), Loops provide compounding intelligence (moat). This is the feature that makes brands fundamentally better over time, not just slightly faster today.

*System Architecture:*

```
Spaces (Content Generation)
    ↓
Loop Orchestrator (Plan → Make → Test → Learn)
    ↓
Testing Pipeline (Simulate → Listen → Test)
    ↓
Performance Tracking (Meta API, Shopify API, GA4)
    ↓
RL Model (Pattern Recognition)
    ↓
Brand Memory (Learning Storage)
    ↓
Next Generation (Biased by Learnings)
    ↓
Repeat ∞
```

## 2. SCOPE

### In Scope

*Core Loop Infrastructure:*

- Loop creation modal (from any Space)
- Loop configuration (name, metric, frequency, volume, testing mode)
- Loop orchestration engine (triggers generations, manages state transitions)
- Loop dashboard (view all active/paused Loops, performance trends)
- Generation tracking (Gen 1, Gen 2, ..., Gen N with timestamps)
- Manual controls (pause, resume, force regenerate, kill Loop)

*Testing Mode 1: Simulate (SimGym)*

- AI agent simulation system
- Historical data calibration (train agents on store's past behavior)
- Variant browsing simulation (agents interact with generated content)
- Predictive scoring (CTR, engagement, friction points)
- Heatmap generation (where users will look/click)
- Confidence scoring (how reliable is prediction)

*Testing Mode 2: Listen (Interactive User Testing)*

- Story-style swipeable interface (mobile-first)
- Variant presentation (show 2-5 options in fullscreen carousel)
- User voting system (swipe right = prefer, left = dislike)
- Feedback collection ("Why did you choose this?" text input)
- Reward mechanism (discount codes, early access, loyalty points)
- Response aggregation (preference percentages, common themes)

*Testing Mode 3: Test (Live A/B Testing)*

- Deployment to live channels (Shopify, Amazon, headless sites)
- Traffic splitting (50/50, 33/33/33, custom ratios)
- Statistical significance tracking (confidence intervals, p-values)
- Real-time performance monitoring (CTR, CVR, ROAS)
- Auto-promotion logic (winner takes 100% traffic when significant)
- Rollback capability (revert to control if performance drops)
- Two deployment modes:
    - *Direct Mode:* Automatic asset swapping, all traffic sees variants
    - *Opt-In Mode:* "View with AI" toggle, only opted-in users see variants

*Performance Tracking Integration:*

- Meta Ads API (impressions, clicks, CTR, spend, ROAS)
- Shopify Analytics API (product views, ATC rate, purchases)
- Google Analytics 4 (traffic, bounce rate, conversion funnels)
- Amazon API (A+ content performance, click-through)
- Custom pixel tracking (for headless commerce)

*Pattern Learning (RL Model):*

- Visual feature extraction (colors, composition, layout, elements)
- Text feature extraction (sentiment, structure, length, hooks)
- Performance correlation analysis (which features drive results)
- Statistical significance testing (avoid false patterns)
- Confidence scoring (how reliable is pattern)
- Bias generation (increase probability of high-performing features)
- Exploration/exploitation balance (70% learned patterns, 30% new exploration)

*Loop Memory & Brand Memory Integration:*

- Loop-specific memory (stores all generations, performance, patterns)
- Brand Memory integration (learned patterns feed global brand intelligence)
- Pattern surfacing (dashboard shows "Top 3 Learned Patterns")
- Manual pattern review (users can see why RL biased generation)

## 6. BEHAVIORS & RULES

### Loop Creation Behavior

- *Validation:* Can't start Loop without deployment target if "Test" mode selected
- *Defaults:* If no testing mode selected, default = all 3
- *First Generation:* Triggers immediately on Loop creation
- *Naming:* Auto-suggest Loop name based on Space

### Loop Orchestration Behavior

*Pipeline Sequencing:*

```
Space generates variants → Simulate (if enabled) → Listen (if enabled) → Test (if enabled) → Learn → Wait → Repeat
```

*Stage Failures:*

- If Simulate fails → Skip to Listen with all variants
- If Listen fails → Skip to Test with all variants
- If Test deployment fails → Mark generation as failed, retry next

### SimGym (Simulate Mode) Behavior

*Agent Calibration:*

- Load last 90 days of store data
- Train agents on bounce rate, ATC rate, purchase rate
- Create 10 agent profiles (frequent buyer, browser, price-sensitive, etc.)

*Simulation:*

- Each agent "views" each variant
- Generate heatmap (visual saliency)
- Predict action: click, scroll, bounce, add-to-cart
- Aggregate across agents → predicted CTR/CVR

*Confidence Scoring:*

- High (>80%): Large dataset, low variance
- Medium (60-80%): Moderate dataset, medium variance
- Low (<60%): Small dataset or high variance

### Listen Mode Behavior

*Interface Display:*

- Fullscreen story carousel
- One variant per screen
- Swipe gestures: right (prefer), left (dislike), down (skip)

*Feedback Collection:*

- Optional prompt after vote
- Text input, 500 char max
- No mandatory fields

*Reward Mechanism:*

- Show reward upfront
- Generate unique discount code on completion
- Track redemption rate

*Response Aggregation:*

- Target: 50 responses (minimum 30)
- If <30 after 7 days → skip to Test with all variants
- Calculate preference %
- Text analysis for common themes
- Top 3 by preference % advance

### Test Mode Behavior

*Deployment:*

- *Direct Mode:* Replace live assets automatically, all traffic sees variants
- *Opt-In Mode:* "View with AI" toggle, only opted-in users see variants

*Traffic Splitting:*

- Hash user ID to variant assignment
- Consistent experience per user
- Server-side enforcement

*Performance Tracking:*

- Poll APIs every 4 hours
- Calculate statistical significance
- Minimum sample: 100 impressions per variant

*Auto-Promotion:*

- When winner reaches 95% confidence → promote to 100% traffic
- User can disable auto-promotion
- Winner becomes new control

*Rollback:*

- If variant drops >10% vs control → auto-revert
- User can disable auto-rollback
- Manual rollback available anytime

### Pattern Learning Behavior

*Feature Extraction:*

- *Visual:* Colors, composition, product size, background type, text overlay
- *Text:* Sentiment, length, structure, hook type, emotional tone

*Correlation Analysis:*

- Compare high vs low performers
- Calculate correlation coefficient

*Statistical Testing:*

- Require p<0.05 for significance
- Minimum sample: 5 high + 5 low performers
- Test on holdout set (20% of data)

*Confidence Scoring:*

- Based on sample size, effect size, variance
- High (>80%), Medium (60-80%), Low (<60%)

*Bias Generation:*

- Increase probability of high-performing features
- Maintain 30% exploration

### Loop State Transitions

```
Created → Active (first generation triggered)
Active → Paused (user clicks pause)
Paused → Active (user clicks resume)
Active → Completed (all planned generations finished)
Active → Failed (critical error)
Failed → Active (user fixes issue, resumes)
```

### Edge Case Behaviors

1. *No deployment target:* Run Simulate + Listen only, skip Test
2. *Platform API fails:* Retry 3x, then skip stage, log error
3. *Low Listen response (<30):* Skip to Test with all variants
4. *Insufficient performance data:* Extend Test period by 7 days
5. *Negative performance:* Auto-pause Loop, notify user
6. *Concurrent Loops on same target:* Warn user, allow anyway

## 7. TECHNICAL CONSTRAINTS & EDGE CASES

### Performance Requirements

- *Loop Dashboard Load:* <1 second
- *Loop Creation:* <3 seconds
- *SimGym Execution:* <10 minutes for 20 variants
- *Listen Response Aggregation:* <1 second
- *Test Deployment:* <5 minutes
- *Performance Data Sync:* Every 4 hours (±15 min)
- *RL Model Pattern Learning:* <1 hour after Test completes

### Scalability Constraints

*Max Loops per User:*

- Free: 1 active Loop
- Pro: 5 active Loops
- Enterprise: Unlimited

*Other Limits:*

- Max Variants per Generation: 50
- Max Generations per Loop: Unlimited
- Max Listen Responses: 1000 per session
- Concurrent Test Deployments: 10 per platform

### API Rate Limits

- *Meta Ads API:* 200 calls/hour per user (batch all Loops in single call, cache 4 hours)
- *Shopify API:* 2 calls/second burst, 40 calls/10sec sustained (queue deployments)
- *Google Analytics 4:* 100K requests/day (batch queries)
- *SimGym (Internal):* 100 concurrent simulations (queue beyond)

### Error Handling

*1. Space Execution Errors:*

- Space fails → Retry 3x, then mark generation failed
- Partial generation → Proceed with available variants
- Invalid output → Skip invalid, proceed with valid

*2. SimGym Errors:*

- Insufficient data → Show warning, proceed
- Calibration fails → Skip SimGym, go to Listen
- Timeout (>30 min) → Cancel, proceed with random top 5

*3. Listen Mode Errors:*

- Low response rate → Send reminder, extend deadline
- Spam detected → Filter out, require min 20 unique users
- Reward system fails → Log error, manually provide codes

*4. Test Deployment Errors:*

- API auth expired → Notify user, pause Loop
- Asset upload fails → Retry 3x, then notify
- Traffic splitting fails → Revert to control

*5. Performance Data Errors:*

- Incomplete data → Use if >50% complete, else skip sync
- Attribution mismatch → Log warning, show "Data may be inaccurate"
- Zero impressions after 7 days → Extend Test by 7 days

### Edge Cases

*1. Conflicting Loops:* Warn but allow (Loops run independently)

*2. Seasonal Anomalies:* Normalize data (week-over-week comparison)

*3. Platform Policy Violations:* Remove variant, proceed with others

*4. Data Inconsistencies:* Trust platform-specific data

*5. User Behavior:* Handle pause mid-Test, deleted targets, metric changes

*6. RL Model:* Handle equal performance, dominant variants

### Browser Compatibility

- Listen Mode UI: iOS Safari 14+, Android Chrome 90+
- Fallback: Button-based voting if swipe unsupported

### Accessibility

- SimGym Results: Text alternatives for heatmaps
- Listen Mode: Keyboard navigation
- Test Dashboard: Screen reader compatible (ARIA labels)
