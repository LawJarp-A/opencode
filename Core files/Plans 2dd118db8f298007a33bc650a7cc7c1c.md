# 📋 SHAPE UP PITCH

## Problem

Brands don't think in workflows. They think in outcomes.

*Today's broken reality:*

```
User: "I need to launch my new product"
ShopOS: "Here are 57 Spaces you can use!"
User: "...which ones? In what order?"
ShopOS: [silence]
  ↓
User manually discovers → sequences → executes → compiles
  ↓
Result: Confusion, incomplete work, 38% abandonment
```

*The gap:* Spaces solve discrete tasks brilliantly. But brands work in *campaigns, launches, seasons* - not isolated steps. They need *deliverable packs*, not individual outputs.

*Real user pain:* "I spent 6 hours across 3 days figuring out which Spaces to use for a product launch, then another 2 hours organizing the outputs. I ended up missing the Amazon listing images and had to start over. This should've been one button."

## Appetite

*6 weeks*

Plans are the GTM demo. "Watch us launch your product in 45 minutes" is the pitch that closes deals. Without Plans, users see a toolkit. With Plans, they see outcomes.

We're investing 6 weeks because Plans are the bridge between "cool AI toy" and "essential business tool."

## Solution

*Plans = Pre-Built Workflow Chains That Deliver Complete Outcomes*

Not individual tools. Not manual sequencing. *End-to-end execution in a single click.*

*The Experience:*

```
User states goal: "Launch new product"
  ↓
Plan shows preview: "This will create 20-30 assets across 4 categories"
  ↓
User fills unified form: Product info, brand context, channels (one time)
  ↓
Plan executes: 5-15 Spaces automatically (sequential + parallel)
  ↓
Progress bar: "Generating catalog shots... (Step 3 of 12)"
  ↓
45 minutes later
  ↓
Complete deliverable pack: Organized folders, deployment-ready files
  ↓
User downloads or deploys directly to Shopify/Meta/Amazon
```

*The Architecture:*

- *Input:* Single unified form (collect all data once)
- *Execution:* Chain 5-15 Spaces (sequential dependencies + parallel batching)
- *Orchestration:* Progress tracking, error recovery, partial outputs
- *Output:* Organized deliverable pack (folder structure, file naming, deployment-ready)

*4 Launch Plans:*

1. *New Product Launch* (45 min)
    - Catalog creation (20-30 assets: studio, lifestyle, creative, video)
    - Marketplace adaptation (Amazon, Etsy, website formats)
    - Marketing assets (10 ad variations, 5 social posts)
    - Copy & metadata (titles, descriptions, bullets, tags)
2. *Seasonal Campaign Refresh* (2 hours)
    - Trend intelligence (scrape TikTok/Pinterest/Instagram)
    - Campaign creative generation (15 ads per product, seasonal overlays)
    - Social content pack (20 posts, 10 videos, 5 pins)
    - Deployment (push to Meta, Shopify, export social)
3. *Marketplace Expansion* (3 hours)
    - Asset adaptation (resize for Amazon/Etsy/Faire specs)
    - Copy rewrite (platform-specific tone, keywords)
    - Listing creation (CSV/XML feeds, bulk upload)
4. *Competitor Response Sprint* (4 hours)
    - Competitor analysis (scrape campaign, identify patterns)
    - Counter-positioning (differentiated messaging)
    - Rapid creative generation (20 ads, 10 social posts)
    - Speed deployment (draft campaigns, tracking dashboards)

*Why This Works:*

- *Mental model alignment:* "Launch product" not "run 12 Spaces"
- *Time compression:* Weeks → Hours
- *Proven paths:* No guessing, embedded best practices
- *Complete outputs:* Not fragments, full deliverable packs

## Rabbit Holes

*Don't build:*

- *Custom Plan builder UI.* Plans are JSON configs. Workflow team edits configs, not users. Custom Plans = Planning Mode (Phase 2).
- *Real-time collaboration.* Plans run for one user. No multi-user editing mid-execution.
- *Plan versioning/forking.* Use fixed Plan definitions. Updates apply to all users.
- *Conditional logic engine.* Keep execution linear. If/then branching = Planning Mode.
- *Deep analytics per Plan step.* Track Plan-level success, not per-Space metrics within Plan.
- *AI-suggested Plans.* Don't auto-recommend "You should run X Plan." User-initiated only.

*Reuse existing:*

- Space execution engine (already chains Spaces)
- Files library (store outputs)
- Brand Memory (provide context to Spaces)
- Refine™ (escalation path)

*Watch out for:*

- *Dependency failures.* If Space 3 fails, how do Spaces 4-12 proceed?
- *Long execution times.* 2-4 hours is acceptable, but need clear progress.
- *Input form complexity.* Unified form must collect everything, but not overwhelm.
- *Output organization.* 30 files dumped in one folder = bad UX.

## No-Gos

*Explicitly NOT doing:*

- ❌ Custom Plan creation (users can't build Plans - that's Planning Mode)
- ❌ Plan editing mid-execution (can't modify after start)
- ❌ Real-time collaboration (one user per Plan run)
- ❌ Plan marketplace (users can't share/sell Plans)
- ❌ Conditional branching (if/then logic)
- ❌ Per-step analytics (only Plan-level metrics)
- ❌ Plan scheduling (run later, recurring Plans = Phase 2)

### Plan Selection & Preview

1. Display 4 Plan cards on dedicated `/plans` page
2. Each card shows: name, description, estimated time, output preview, example use case
3. "Start Plan" button opens unified input form
4. Preview modal shows full execution flow (Spaces that will run, outputs generated)

### Unified Input Form

1. Dynamic form based on Plan requirements
2. Each Plan has different input fields (product photos vs campaign theme)
3. Form validation before Plan starts (required fields, file formats)
4. Brand Memory auto-fills context fields (user can override)
5. "Start Execution" button triggers Plan

### Execution Orchestration

1. Plan executes Spaces in defined sequence
2. Sequential dependencies: Space B waits for Space A output
3. Parallel batching: Spaces C, D, E run simultaneously (if no dependencies)
4. Each Space receives inputs from previous Spaces + Brand Memory
5. Space outputs stored temporarily (compiled at end)
6. Progress updates every 10 seconds

### Progress Tracking

1. Overall progress bar (0-100%)
2. Current step indicator ("Step 5 of 12: Generating marketplace adaptations...")
3. Time remaining estimate (based on avg execution times)
4. Completed steps list (checkmarks)
5. User can minimize (Plan runs in background)
6. User can cancel (confirmation modal: "Cancel and discard all outputs?")

### Error Recovery

1. If Space fails → Retry 3x automatically
2. If retries fail → Mark step as failed, continue to next step
3. Final output includes partial results + error report
4. User can re-run failed steps manually
5. Critical failures (e.g., input error) → Abort Plan, refund credits

### Output Organization

1. All outputs saved to folder structure (defined per Plan)
2. Folder naming: `/{Plan_Name}_{Product}_{Date}/`
3. File naming: Descriptive, sequential (e.g., `studio_front.jpg`, `meta_ad_1.jpg`)
4. Manifest file (JSON): Metadata, usage instructions, deployment guides
5. Auto-save to Files library (with "Plan Output" tag)

### Completion & Deployment

1. Completion modal shows: total outputs, folder structure preview, download/deploy options
2. "Download All" button (ZIP file)
3. "View in Files" button (opens Files library filtered to Plan outputs)
4. "Deploy" buttons (platform-specific, if applicable):
    - "Deploy to Shopify" → Bulk upload images to products
    - "Deploy to Meta" → Create draft campaigns in Ads Manager
    - "Deploy to Amazon" → Generate listing feed
5. "Send to Refine™" button (escalate entire output to expert for review)

## 6. BEHAVIORS & RULES

### Plan Execution Flow

```
User selects Plan → Preview shown → Input form filled → Validation → Execution starts
  ↓
Space 1 executes → Output stored
  ↓
Space 2 executes (uses Space 1 output) → Output stored
  ↓
Spaces 3, 4, 5 execute in parallel → Outputs stored
  ↓
Space 6 executes (uses Spaces 3-5 outputs) → Output stored
  ↓
... [repeat for all Spaces in Plan]
  ↓
All Spaces complete → Compile outputs into folder structure → Show completion modal
```

### Dependency Management

- Plans define dependencies in JSON config:

```json
{
  "steps": [
    {"id": "catalog_studio", "space": "product_studio_shots", "depends_on": []},
    {"id": "catalog_lifestyle", "space": "lifestyle_shots", "depends_on": []},
    {"id": "amazon_adapt", "space": "amazon_optimizer", "depends_on": ["catalog_studio"]},
    {"id": "ads_gen", "space": "ad_creative_gen", "depends_on": ["catalog_lifestyle"]}
  ]
}
```

- Orchestrator builds execution graph
- Parallel execution when possible (no dependencies)
- Sequential when required (downstream needs upstream output)

### Progress Calculation

- Each Space assigned weight (based on avg execution time)
- Progress = (Sum of completed Space weights) / (Total Plan weight)
- Example: Plan has 10 Spaces, each 10% weight → Space 3 completes → 30% progress
- Weighted by actual time: Heavy Spaces (video gen) = 20%, light Spaces (copy gen) = 5%

### Error Handling Behavior

*Space Failure:*

- Retry 3x with exponential backoff (5s, 15s, 45s)
- If all retries fail → Log error, mark step failed, continue Plan
- Final report includes: "Step 4 failed: [error message]. 11 of 12 steps completed."

*Critical Input Errors:*

- Missing required field → Block execution, show error in form
- Invalid file format → Block execution, suggest correct format
- API auth failure (Shopify/Meta) → Pause execution, prompt user to re-auth

*Partial Outputs:*

- Plan completes even if 2-3 Spaces fail
- Deliverable pack includes what succeeded
- Missing outputs clearly marked in manifest: "Amazon infographics: FAILED (error log)"

### Plan Cancellation

- User clicks "Cancel Plan" during execution
- Confirmation modal: "Cancel Plan? All progress will be lost. Outputs will not be saved."
- If confirmed → Stop current Space, discard all outputs, refund credits
- If user navigates away (closes tab) → Plan continues in background, outputs saved

## 7. TECHNICAL CONSTRAINTS & EDGE CASES

### Performance Requirements

- *Plan completion time:* Match estimates ±20% (45 min Plan → 36-54 min actual)
- *Progress updates:* Every 10 seconds
- *Parallel execution:* Up to 5 Spaces simultaneously
- *Error recovery:* Retry within 2 minutes (don't stall Plan)

### Scalability Constraints

- *Max Spaces per Plan:* 20 (prevent 8-hour Plans)
- *Max parallel Spaces:* 5 (prevent API rate limit crashes)
- *Max output files:* 200 per Plan (prevent storage bloat)
- *Max concurrent Plans per user:* 3 (prevent resource exhaustion)

### Plan Configuration (JSON Schema)

```json
{
  "plan_id": "new_product_launch",
  "name": "New Product Launch",
  "description": "Complete asset pack for launching a new product across all channels",
  "estimated_time_minutes": 45,
  "estimated_outputs": 25,
  "input_schema": {
    "product_photos": {"type": "files", "min": 3, "max": 10, "formats": ["jpg", "png"]},
    "product_name": {"type": "text", "required": true},
    "launch_channels": {"type": "multi_select", "options": ["Shopify", "Amazon", "Etsy", "Meta"]}
  },
  "steps": [
    {
      "id": "catalog_studio",
      "space": "product_studio_shots",
      "depends_on": [],
      "inputs": {"photos": "{{input.product_photos}}"},
      "weight": 0.15
    },
    {
      "id": "amazon_adapt",
      "space": "amazon_optimizer",
      "depends_on": ["catalog_studio"],
      "inputs": {"images": "{{catalog_studio.output}}"},
      "weight": 0.10
    }
  ],
  "output_structure": {
    "catalog": ["catalog_studio", "catalog_lifestyle"],
    "marketplace": ["amazon_adapt", "etsy_adapt"],
    "ads": ["meta_ads", "google_ads"],
    "copy": ["product_desc", "ad_copy"]
  }
}
```

### Error Handling

*1. Space Execution Errors:*

- Timeout (Space runs >20 min) → Cancel Space, retry
- Model failure → Retry 3x, mark failed if all fail
- Insufficient credits → Pause Plan, prompt user to add credits, resume

*2. Input Validation Errors:*

- Missing required field → Show error in form, block execution
- File too large (>50MB) → Show error, suggest compression
- Invalid URL (Shopify catalog) → Test URL, show error if unreachable

*3. Dependency Errors:*

- Upstream Space fails → Downstream Space skipped (marked as "Blocked")
- Example: Catalog generation fails → Amazon adaptation skipped
- Final output includes partial results + blocked steps list

*4. Platform Integration Errors:*

- Shopify API down → Retry 3x, fallback to manual export (CSV)
- Meta Ads auth expired → Pause Plan, prompt re-auth, resume

### Edge Cases

*1. User Cancels Mid-Execution:*

- Save partial outputs? No, discard all (avoid clutter)
- Refund credits? Yes, refund for incomplete Spaces

*2. Long-Running Plans (4+ hours):*

- Send email notification when complete
- Show "Plan running in background" indicator in nav
- User can close browser, Plan continues server-side

*3. Plan Runs Overnight:*

- No issue, server-side execution
- User sees completed Plan next morning

*4. Multiple Plans Running:*

- User can run up to 3 Plans concurrently
- Show all Plans in "Active Plans" panel
- Each Plan has independent progress bar

*5. Plan Output Too Large:*

- Max 200 files per Plan
- If exceeded → Bundle into ZIPs (e.g., `/ads/meta_ads_[1-50.zip](http://1-50.zip)`)
