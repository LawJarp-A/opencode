# 📋 SHAPE UP PITCH

## Problem

Some users prefer talking over typing. Creative briefs require filling forms, but forms assume you know exactly what you need. Typing interrupts creative flow.

*The pattern:*

```
User wants to create campaign
  ↓
Faces blank form: "Product name, target audience, tone, channels..."
  ↓
Stares at screen: "I don't know how to describe the vibe I want"
  ↓
Struggles to articulate visual concepts in text
  ↓
Gives up or creates mediocre brief
```

*Real user insight:* "I can describe what I want to a designer in 2 minutes on a call. But typing it into a form takes 15 minutes and I still don't capture the vibe."

*Why voice works:*

- Natural for creative direction ("I want something bold, like that Nike campaign but warmer")
- Real-time clarification (AI asks questions, you refine)
- No writer's block (just talk)
- Captures nuance (tone, energy, references)

## Appetite

*2 weeks*

Call is a differentiation play, not a core feature. It's the "wow" moment in demos: "You can literally just talk to ShopOS." But it's not critical path for V3 launch.

We're investing 2 weeks because the tech is mature (Eleven Labs, Whisper) and the UX is simple (orb, conversation, brief).

## Solution

*Call = Voice-First Creative Director*

Not a chatbot with voice input. A conversational creative partner you talk to like a real creative director.

*The Experience:*

```
User clicks "Talk to Creative Director"
  ↓
Eleven Labs orb appears (pulsing, listening)
  ↓
User speaks: "I need ads for our new winter jacket. Target is outdoor enthusiasts, 25-40. Think Patagonia vibe but more urban."
  ↓
AI responds (voice): "Got it. What's the primary goal—brand awareness or conversions?"
  ↓
User: "Conversions. We're launching in 2 weeks."
  ↓
AI: "Perfect. How many ad variations do you need?"
  ↓
User: "Maybe 10?"
  ↓
AI: "Great. I'll create 10 ad variations with an urban outdoor vibe, targeting 25-40 year olds, focused on conversions. Sound good?"
  ↓
User: "Yes."
  ↓
AI: "Awesome. Generating your brief now."
  ↓
Call ends → Brief appears as editable form
  ↓
User clicks "Work on this brief" → Plan executes
```

*Key Principle:* Voice for **input**, visual UI for **review and execution**. Once brief is generated, shift to text interface for editing and workflow management.

*Technical Stack:*

- *Voice input:* Browser Web Audio API → Whisper (speech-to-text)
- *Conversation:* Claude 4 Sonnet (conversational AI, brief structuring)
- *Voice output:* Eleven Labs (text-to-speech, orb visualization)
- *Brief generation:* Structured output → Form component (editable)
- *Execution:* Same orchestration as Plans

## Rabbit Holes

*Don't build:*

- *Custom voice models.* Use Eleven Labs out-of-box voices.
- *Advanced noise cancellation.* Basic browser-level handling is fine.
- *Call history/replay.* Transcript saved but no audio playback.
- *Multi-turn editing via voice.* Brief editing happens in text UI.
- *Voice commands during execution.* Voice ends when brief is generated.

*Reuse existing:*

- Form components (brief display)
- Plan execution engine (workflow orchestration)
- Brand Memory (auto-fill context)

*Watch out for:*

- Browser compatibility (Safari, Firefox audio APIs)
- Latency (voice → text → AI → text → voice round-trip)
- Conversation drift (user rambles, AI must refocus)
- Accents/background noise (Whisper quality varies)

## No-Gos

*Explicitly NOT doing:*

- ✖ Custom voice training (use Eleven Labs defaults)
- ✖ Multi-language support (English only for Phase 1)
- ✖ Voice editing of briefs (voice for creation only)
- ✖ Call recording/playback (transcript only)
- ✖ Voice commands during execution ("pause", "cancel")
- ✖ Phone call integration (web-only)

# 🔧 ENGINEERING PRD

## 1. OBJECTIVE

*Purpose:*
Build a voice-first interface for creating creative briefs through natural conversation. Enable users to describe what they want by talking, not typing. Generate structured briefs from unstructured voice input.

*Goal:*

- Voice brief completion rate >80% (users who start, finish)
- Brief accuracy: <20% of users make edits post-generation
- Time savings: 50% faster than text input (2 min voice vs 4 min typing)
- Adoption: 20% of users try voice at least once

*Context:*
Call is a differentiation feature. It makes ShopOS feel magical and accessible. It's not critical for core workflows but creates "wow" moments in demos and onboarding.

## 2. SCOPE

### In Scope

*Voice Interface:*

- "Talk to Creative Director" button (accessible from dashboard, Spaces, Plans)
- Eleven Labs orb visualization (3 states: connecting, listening, talking)
- Web Audio API integration (browser microphone access)
- Whisper integration (speech-to-text)
- Eleven Labs integration (text-to-speech, real-time streaming)

*Conversation Flow:*

- AI asks clarifying questions (goal, audience, tone, volume, timeline)
- User responds naturally (conversational, not structured)
- AI confirms understanding ("So you want X, Y, Z. Sound good?")
- User approves → Brief generated

*Brief Generation:*

- Transcript analyzed → Structured brief created
- Brief displayed as editable form component
- Fields: Project name, goal, target audience, tone, channels, asset volume, timeline
- "Work on this brief" button triggers execution

*Execution:*

- Same orchestration as Plans (chain Spaces, deliver outputs)
- Progress tracking, error recovery, completion UI

### Out of Scope (Phase 2)

- Multi-language support (Spanish, French, etc.)
- Call recording/playback
- Voice editing of briefs
- Advanced noise cancellation
- Phone call integration
- Voice commands ("start over", "pause")

*Phase:* Phase 1 (MVP) - 2 weeks

## 5. CORE REQUIREMENTS

### Voice Interface

1. "Talk to Creative Director" button visible on dashboard
2. Click opens orb interface (fullscreen or modal)
3. Orb states:
    - *Connecting:* Static orb, "Connecting..."
    - *Listening:* Pulsing orb, "I'm listening..."
    - *Talking:* Animated orb, voice plays
4. Microphone permission requested (browser native prompt)
5. Audio captured via Web Audio API
6. "End Call" button visible (user can hang up anytime)

### Speech-to-Text (Whisper)

1. Audio stream sent to Whisper API in real-time
2. Transcription latency <500ms
3. Handles common accents (US, UK, Australian English)
4. Basic noise filtering (ignore background music, keyboard clicks)
5. Punctuation and capitalization applied

### Conversation AI (Claude)

1. System prompt:
    - "You are a creative director helping a brand create a brief."
    - "Ask clarifying questions: goal, audience, tone, channels, volume, timeline."
    - "Keep it conversational. Confirm understanding before finalizing."
2. Conversation flow:
    - AI asks 3-5 questions
    - User responds naturally
    - AI confirms: "So you want X. Sound good?"
    - User approves → Brief generated
3. Handles interruptions (user talks over AI → AI stops, listens)
4. Handles restarts ("Actually, let me start over" → AI resets)

### Text-to-Speech (Eleven Labs)

1. AI responses converted to speech via Eleven Labs API
2. Voice: Professional, friendly, conversational (default Eleven Labs voice)
3. Latency <1 second (text → audio)
4. Streaming: Audio plays as it's generated (not wait for full response)
5. Orb visualization syncs with audio (pulses match speech rhythm)

### Brief Generation

1. After user approves, transcript analyzed
2. Extract structured data:
    - Project name (inferred or default: "[Asset Type] Campaign")
    - Goal (brand awareness, conversions, engagement)
    - Target audience (age, demographics, psychographics)
    - Tone (adjectives, references)
    - Channels (Meta, Instagram, TikTok, email, etc.)
    - Asset volume (how many outputs)
    - Timeline (launch date or urgency)
3. Brief displayed as editable form (same component as Plans)
4. "Work on this brief" button at bottom

### Execution

1. "Work on this brief" triggers workflow orchestration
2. Brief maps to Plan or custom workflow
3. Progress tracking (same UX as Plans)
4. Outputs saved to Files library
5. User notified when complete

## 6. BEHAVIORS & RULES

### Conversation Guidelines

*AI should:*

- Ask open-ended questions ("What's your goal?" not "Is it conversions?")
- Confirm understanding ("So you want X, Y, Z?")
- Keep it brief (AI responses <30 seconds)
- Handle vague input ("Make it cool" → "What style feels 'cool' to you?")

*AI should NOT:*

- Lecture (no long explanations)
- Overcomplicate (max 5 questions)
- Repeat information (user said it once, move on)
- Force structure (let conversation flow naturally)

### User Interruption Handling

- If user speaks while AI is talking:
    - AI stops immediately
    - AI listens to user
    - AI responds to new input
- No "Please wait for me to finish" messages

### Error Recovery

*Scenario 1: User says "I don't know"*

- AI offers suggestions: "No problem. Are you launching a product, running a campaign, or something else?"

*Scenario 2: User rambles off-topic*

- AI refocuses: "Got it. Let's nail down the core brief. What's the main goal?"

*Scenario 3: Audio quality issues*

- AI says: "Sorry, I didn't catch that. Can you repeat?"
- If 3x failures → Offer text fallback: "Having trouble hearing. Want to type instead?"

*Scenario 4: User hangs up mid-conversation*

- Save partial transcript
- Show: "Call ended. Want to finish your brief in text?"
- Option to resume or discard

### Brief Accuracy Validation

*After generation, check:*

1. All required fields populated? (goal, audience, asset type)
2. Conflicting info? ("10 posts" but "video" → Flag as error)
3. Missing critical context? (no timeline → Default to "ASAP")

*If validation fails:*

- Highlight missing/conflicting fields in red
- User can edit before execution

## 7. TECHNICAL CONSTRAINTS & EDGE CASES

### Performance Requirements

- Voice latency: <500ms (user speaks → transcript appears)
- AI response time: <2 seconds (transcript → AI response text)
- TTS latency: <1 second (text → audio plays)
- Total round-trip: <4 seconds (user stops talking → AI starts talking)

### Browser Compatibility

- Chrome/Edge: Full support
- Safari: Full support (test microphone permissions)
- Firefox: Full support
- Mobile (Chrome, Safari): Basic support (no orb animations, simpler UI)

### Audio Quality

- Minimum sample rate: 16kHz
- Handles background noise: Basic (keyboard, mouse clicks ignored)
- Fails gracefully: If audio too noisy → Prompt user to move to quieter space

### Conversation Length Limits

- Max conversation time: 5 minutes
- Max AI questions: 7 (prevent endless questioning)
- If exceeded → Auto-generate brief with available info

### Error Handling

*1. Microphone Access Denied:*

- Show error: "Microphone access required. Please enable in browser settings."
- Offer text fallback: "Or create brief with text instead."

*2. Whisper API Failure:*

- Retry 2x
- If fails → Show: "Voice transcription error. Switching to text input."
- Fall back to text form

*3. Eleven Labs API Failure:*

- AI responses show as text (chat bubbles)
- User can still continue conversation via voice or text
- Orb visualization disabled

*4. Network Latency >10s:*

- Show loading indicator
- After 10s → "Slow connection detected. Continue?"
- Option to cancel or wait

### Edge Cases

*1. User speaks multiple languages:*

- Detect language (Whisper auto-detects)
- If non-English → Show: "English only for now. Switch to text?"

*2. User provides no useful info:*

- After 3 min of vague responses → AI says: "I'm having trouble understanding. Let me ask differently..."
- If still vague → Offer text: "Want to type instead?"

*3. User contradicts themselves:*

- AI clarifies: "Earlier you said X, now you're saying Y. Which is correct?"

*4. User wants to edit mid-conversation:*

- User: "Wait, change that to 20 ads, not 10."
- AI: "Got it, 20 ads. Anything else?"
